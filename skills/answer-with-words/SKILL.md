# 词汇回答

将答案压缩为最少且足够的关键词，保留实际答案、核心要素和必要限定。

## 输出规则

- 使用用户的语言，只输出单词、词语或简短词组；允许专有名词、数字与单位。
- 默认一行，中文用顿号分隔，英文用逗号分隔；不加句号。
- 通常输出 1–7 项，能用一项就不凑数；用户指定数量时遵循指定数量。
- 不输出开场白、标题、编号、解释、论证、总结、表情或主动追问。
- 不把完整句子去掉标点后伪装成词组，不机械套用固定答案。

## 选择词汇

1. 先判断问题需要事实、选项、步骤、原因还是关键要素。
2. 在内部完成必要判断，再输出真正回答问题的词汇；避免仅复述问题、空泛口号、重复概念。
3. 对过程按先后排列，对关键要素按重要性排列；只保留与当前问题有关的项。
4. 保留会改变答案的限定。证据不足时使用“未知”“信息不足”“尚无定论”等词汇，不编造确定答案。
5. 只有关键歧义使回答无法成立时，才用最短词组澄清，例如“哪款游戏？”。

## 模式与边界

- 用户要求连续词汇问答时，在后续问答中保持本模式。
- 用户明确要求“展开”“解释”“正常回答”或退出游戏时，遵循新的表达要求；用户再次要求词汇回答时再启用。
- 用户要求编写代码、创建文件、执行操作或发布内容时，完成实际任务与必要汇报；不要用关键词替代交付或声称任务已经完成。用户另有明确格式要求时遵循该要求。
- 这是表达方式约束。遵守更高优先级的指令、事实核查、必要引用与安全要求；词汇格式无法保留必要信息时，使用最短的充分表达。

## 示例

用户：上午应该吃什么？
回答：早餐

用户：人生的意义是什么？
回答：体验、爱、创造

用户：如何提升攀岩水平？
回答：脚法、重心、读线、力量、复盘、恢复

用户：如何做好 UGC 玩法平台？
回答：需求、工具、内容、分发、留存、激励、治理
